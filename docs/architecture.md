# Архитектура MVP

MAX → Bot (официальный JS SDK) → React Mini App (MAX UI + Bridge) → Fastify → SQLite.
Сервер вызывает отдельные RecommendationEngine → GroupConsensus → PlanBuilder → ExplanationService.

Один процесс API раздаёт production frontend. Бот запускается вторым процессом того же образа. SQLite хранится в volume. Node 24 даёт встроенную SQLite без native build. Исходники написаны на strict TypeScript, модули разделены каталогами.

Вход MAX подтверждается подписью initData и возрастом auth_date. Demo-учётки получают серверный случайный bearer и могут менять только demo-сессии. Ссылка с криптографически случайным ID даёт право присоединиться; она не содержит ответы участников. Личные preferences/veto остаются на сервере, каждому выдаются только его ответы. Обновление ответа повышает revision и сбрасывает устаревший план. Алгоритм никогда не ослабляет вето или бюджет.

Ядро переносится без изменений: групповой опрос, ограничения, расчёт совместимости, планирование и защита личных ответов. Город определяется по геопозиции или поиску по названию. Сервер запрашивает реальные места рядом с общей точкой встречи. Для Москвы, Санкт-Петербурга и Казани предусмотрены расширенные списки точек сбора.

Ограничения: один сервер SQLite, polling состояния mini app, прямолинейная оценка расстояния и приблизительное пешее время; карты открываются внешней URL-ссылкой. Наличие мест и бронирование не проверяются. Каталог MVP синтетический. Постоянный HTTPS и регистрация mini app у организаторов — отдельные условия реального MAX запуска, не заменяемые локальным Docker.

## Версия 0.2: общее ядро для чата и mini app

Bot API update → BotController → Sessions → SQLite ← Sessions ← HTTP API ← Mini app/браузер.

`Sessions` содержит единые создание, присоединение, ограничения доступа, расчёт и sharing. Бот использует подтверждённого отправителя события MAX; HTTP API — подписанный initData или сессию, обменянную на одноразовый билет из личного чата. ID одинаковый во всех интерфейсах. Бот и API монтируют только собственную папку данных проекта; SQLite WAL и busy_timeout обеспечивают запись двумя процессами, а revision/CAS защищает план от устаревшего расчёта.

BotState хранит черновики, обработанные события, привязки групп и ID редактируемой карточки. Данные чужих приложений сервера недоступны через эти mounts. При масштабировании shared volume заменяется отдельным серверным API/БД, а BotController остаётся адаптером пользовательского взаимодействия.
