# Демонстрация: 1–2 минуты

## Браузерная демонстрация, без MAX-пользователей

1. Открыть [https://soberemsya.139.100.225.250.sslip.io](https://soberemsya.139.100.225.250.sslip.io) или локальный `http://localhost:3000`. Видна маркировка «Демо вне MAX».
2. «Собрать компанию»: ближайшая дата, 19:00 по Казани, 4 часа, 5 человек, центр Казани.
3. Оставить «Прогулка» + «Вкусно поесть», добавить «Активно», бюджет 1500 ₽, радиус 3 км.
4. На третьем шаге выбрать вето «Кино», создать план.
5. Показать ссылку «Пригласить друзей» и личный ответ. Авторы вето в общем ответе отсутствуют.
6. «Добавить 4 демо-участников». Каждый явно отмечен словом «демо»; это не реальные пользователи MAX.
7. «Найти общий план». Показать шкалу совпадения интересов, остановки, суммарный бюджет, время с переходами, альтернативы.
8. Раскрыть объяснение выбора: бюджет, общее время, радиус и интересы участников видны отдельно.
9. Показать «Вето учтено: Кино» и источник/дату у каждой остановки.
10. «Изменить мой ответ» → выбрать вето одной из категорий текущего плана. Сохранение автоматически пересчитает имеющийся план; исключённой категории больше нет. Если пересечение пустое — приложение объяснит, что можно изменить, не отменяя вето.
11. Открыть маршрут в Яндекс Картах. Это URL-навигация по демонстрационным точкам, не собственный GIS и не проверка площадок.
12. «Поделиться в MAX» открывает карточку предпросмотра; повторная кнопка вызывает выбор получателя MAX. «Скопировать ссылку» — резервный путь. Автоматической отправки в чат нет.

## Настоящий сценарий MAX

Предусловия: постоянный или явно временный HTTPS APP_URL; этот URL подключён организаторами к боту; BOT_TOKEN только в ENV. Бот запущен отдельно или в Compose. Не выдавать localhost-демо за выполнение этого предусловия.

1. Открыть бота команды, отправить `/start`, нажать «Собрать компанию».
2. Пройти те же три шага. Вверху «Внутри MAX»; сервер проверяет подписанный initData.
3. Поделиться приглашением через MAX; открыть его из второго реального аккаунта, заполнить личные предпочтения. Повторить при необходимости.
4. Сформировать результат и поделиться обратно в чат штатным Bridge sharing.
5. Проверить и веб-версию MAX, и телефон. Записать фактические версии клиента и результат в checklist; до этого пункты остаются открытыми.

## Негативные проверки

Один участник → кнопка расчёта недоступна; нет общих вариантов → понятное сообщение; сохранение одинакового ответа не дублирует участника; неизвестная или истёкшая ссылка → отдельная ошибка; выключенная сеть → повторяемое действие без потери серверных ответов.

## Полностью текстовый бот (0.2)

1. `/start` → «Создать встречу». Выбрать дату/время, «Мой вайб», интересы, бюджет/радиус, вето, сохранить.
2. «Пригласить друзей» → отправить ссылку второму человеку. Он проходит свой личный опрос.
3. «Найти общий план» → текст с остановками и картами. «Изменить мой ответ» → другое вето → пересчёт.
4. «Эта встреча в браузере» → личная ссылка → тот же план и собственный ответ. Ссылку не пересылать.
5. После разрешения групп: добавить бота, `/plan` в общем чате → создание в личке → публикация общей карточки → личные ответы друзей → обновление карточки и расчёт.

Для mini app и групп проверить разрешения организаторов. Личный текстовый сценарий их не требует.
