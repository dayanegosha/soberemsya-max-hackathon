# Соберёмся

MAX помогает компании договориться, чем заняться. MVP для трека «Досуг и развлечения», команда **МАХимы**.

**Статус:** приложение работает под HTTPS: [https://soberemsya.139.100.225.250.sslip.io](https://soberemsya.139.100.225.250.sslip.io). Бот [@t243_hakaton_max_bot](https://max.ru/t243_hakaton_max_bot) запущен, mini app подключён. Версия 0.4 определяет город по геопозиции MAX и ищет города России по названию. Для любого выбранного города сервис загружает реальные места рядом из OpenStreetMap. Москва, Санкт-Петербург и Казань дополнительно получили расширенные списки понятных точек встречи. Полный фактический статус проверок — [checklist](docs/hackathon-checklist.md).

## Пользователь и сценарий

Компания от 2 совершеннолетних участников договаривается о встрече в общем чате. Организатор создаёт встречу и делится ссылкой. Каждый выбирает интересы, личный бюджет, доступное время, радиус и одну нежелательную категорию. Алгоритм исключает несовместимые варианты, строит маршрут, объясняет выбор и предлагает альтернативы. Личные ответы и авторы вето не выдаются другим участникам. Маленькая группа всё же может делать косвенные выводы из изменения результата — это не криптографическая анонимность.

Бот: полноценный опрос, приглашения, общие планы и карты прямо в переписке; `/start`, `/help`, `/plan`, `/myplans`, `/status`, `/cancel`. [Личный и групповой сценарии](docs/bot-experience.md). Mini app: три шага, лобби, результат, ссылки на карты, предпросмотр sharing. Совпадение интересов не означает, что участник подтвердил участие.

## Запуск одной командой

Нужны Docker Engine и Compose v2+ (на macOS — Docker Desktop или Colima). Из корня репозитория:

```sh
docker compose up --build
```

Открыть http://localhost:3000. Без токена запускается demo app; сервис bot сообщает, что токен не настроен, и завершается. Для настоящего бота скопировать `.env.example` в `.env`, заполнить BOT_TOKEN, MAX_BOT_USERNAME и APP_URL, повторить команду. `.env` не входит в Git или Docker context. API_URL — адрес для документации/проверяющей системы; браузер обращается к API того же origin.

В Docker: порт приложения 3000, наружу только `127.0.0.1:3000`; SQLite в volume `data`. Внешний reverse proxy/TLS или туннель должен вести к этому порту. `APP_URL` должен точно совпадать с публичным origin; иначе запись блокируется проверкой Origin. Для другого локального порта задать одновременно `PORT` и `APP_URL`.

## Развёрнутый сервер

Изолированная папка `/root/soberemsya-max-243`, отдельный Docker Compose project и собственные данные. Существующие приложения сервера не изменялись. [Управление, обновление и резервное копирование](docs/deployment.md). Шрифт всего интерфейса — VK Sans Display, файлы включены в приложение.

## Без Docker / разработка

Node.js 24+, npm. Все версии библиотек зафиксированы в `package-lock.json`.

```sh
npm ci
npm run build
npm start
```

Для бота в отдельном терминале: `node --env-file=.env --import tsx apps/bot/src/index.ts`. Для разработки интерфейса: API `npm run dev`, frontend `npm run dev:web`; установить `APP_URL=http://localhost:5173`, API по умолчанию на 3000. После правок без Vite dev пересобрать frontend и обновить страницу.

## Переменные окружения

| Переменная | По умолчанию / назначение |
|---|---|
| BOT_TOKEN | Пусто; только backend/bot, никогда браузер |
| MAX_BOT_USERNAME | Публичный ник бота; нужен для настоящих MAX приглашений |
| APP_URL | http://localhost:3000; HTTPS требуется внутри MAX |
| API_URL | http://localhost:3000/api; адрес проверяющего API |
| PORT / HOST | 3000 / 127.0.0.1; внутри контейнера HOST=0.0.0.0 |
| DB_PATH | var/soberemsya.sqlite; внутри контейнера /app/var/soberemsya.sqlite |
| ALLOW_DEMO | true; demo-идентичности изолированы от MAX-сессий |
| MAX_ALLOW_WEBHOOK_REPLACE | false; защита существующей webhook-подписки бота |
| MAX_API_BASE_URL | https://platform-api2.max.ru; применяется только ботом |

Для polling SDK удаляет webhook-подписки. До старта бот проверяет их наличие и отказывается продолжать без явного разрешения. Не запускайте два polling процесса на одном токене.

## Архитектура и данные

- `apps/webapp`: React 19, TypeScript strict, Vite, MAX UI, Bridge.
- `apps/server`: Fastify, схемы Zod, встроенная SQLite Node 24, сессии, идемпотентность и авторизация.
- `apps/bot`: официальный `@maxhub/max-bot-api`.
- `packages/recommendation`: жёсткие фильтры, групповой consensus, детерминированный план до трёх остановок, объяснение.
- `packages/shared`: проверка подписи и срока initData MAX.
- `data/activities.json`: воспроизводимый тестовый набор для автоматических проверок.

Бюджет считается по верхней оценке цены. Время включает занятия, ожидание и приблизительные переходы; возврат не включён. Радиус ограничивает каждую точку относительно места встречи, не общую длину маршрута. Веса мягкого ranking вынесены в `packages/recommendation/src/weights.ts`. Вето/деньги/возраст/время/радиус не ослабляются. Изменение ответа увеличивает revision и сбрасывает прошлый план; сохранение из экрана результата запускает новый расчёт. Чужие ответы видны только агрегированно.

Внешние сервисы: MAX Bot API и CDN Bridge, Nominatim для определения и поиска города, Overpass API для реальных мест рядом, Яндекс Карты для готового маршрута. Данные о режиме работы и наличии мест нужно проверять перед выходом. [Происхождение тестовых данных](data/sources/prepared-data.md), [источники](docs/data-sources.md).

## Demo Mode и проверка

«Собрать компанию» → определить геопозицию или найти город → три шага → «Добавить 4 демо-участников» → «Найти общий план». Указать вето, затем поменять его на категорию из плана: результат обновится. Другой браузер с приглашением позволяет проверить самостоятельное присоединение.

```sh
npm test
npm run build
npm audit
```

[Сценарий для жюри](docs/demo-script.md). Ошибки сессии, отсутствие вариантов, недостаток ответов, неверные параметры и повторные запросы обработаны. API ошибки: `{error:{code,message}}`.

## Текстовый сценарий MAX

Открыть бота → `/start` → «Создать встречу» → короткий опрос → «Пригласить друзей». Город можно выбрать кнопкой или отправить боту геопозицию. Друзья открывают приглашение, отвечают в личке; «Найти общий план» выдаёт маршрут прямо в сообщении. Mini app не требуется. Для группы: добавить бота → `/plan` в группе → настроить встречу в личке → опубликовать приглашение в группе. Общая карточка обновляется, личные ответы остаются скрыты.

Приглашение друзьям не содержит секрета входа. API и бот используют один сервис `Sessions` и одну SQLite в собственном volume проекта.

## Визуальный MAX flow

App/API размещены под HTTPS, бот и mini app работают. Открыть `/start` → кнопку mini app → создать план → второй реальный пользователь → общий результат → поделиться в MAX. Проверить мобильный и веб-клиент. Обычная ссылка localhost не работает у других участников.

Подробности интеграции: [MAX integration](docs/max-integration.md). Полный контракт: `openapi.json`. План автоматической проверки: `DATA-API.yaml`; базовый HTTPS URL уже указан.

## Остановка, повторный запуск и сохранность

`docker compose down` останавливает компоненты и сохраняет volume. `docker compose up -d` запускает их снова. `docker compose logs app bot` показывает технические события без токенов и личных ответов. Не использовать `down -v`, если нужно сохранить встречи. При локальном запуске Ctrl+C; повторно `npm start`. Для согласованной резервной копии остановить **app и bot**, поскольку оба записывают в общую SQLite. Файл SQLite и его WAL нельзя публиковать вместе с исходниками; резервную копию делать после остановки app.

## Известные ограничения и следующий этап

Города России доступны через геопозицию и поиск по названию. Реальные места загружаются рядом с точкой встречи, но сервис не подтверждает расписание, свободные места, бронирование и оплату. Один сервер SQLite; горизонтальное масштабирование не реализовано. Polling интерфейса раз в 3 секунды. Подтверждение принятия плана и полноценная продуктовая аналитика пока не реализованы. В MAX передаются текст и ссылка через системный выбор получателя.

До пилота нужен проверенный каталог реальных площадок и событий, а также фактическая проверка полного группового сценария на нескольких устройствах MAX. Версия исходников сдаётся архивом с SHA-256. После MVP: интервью, метрика реального принятия плана и пилот по [архитектуре](docs/architecture.md).
